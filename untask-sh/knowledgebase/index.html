Untask

Local-first task management for your terminal and desktop. No cloud. No tracking. Your data stays on your machine.

Untask is a CLI and desktop application that manages tasks as plain markdown files inside your project. Use the CLI for scripting and fast edits, or the desktop app for a richer project view backed by the same local files.

  • Tasks are markdown files with YAML frontmatter
  • Everything lives in a .untask/ directory
  • Works with git — commit your tasks alongside your code
  • JSON output mode for scripting and AI agent integration
  • Configurable columns, statuses, and doc patterns

Installation

Build from source

Requires Rust 1.85+ (edition 2024).

git clone https://github.com/mbenhard/untask-sh.git
cd untask-sh
cargo build --release

The binary will be at target/release/untask. Move it to a directory in your $PATH:

cp target/release/untask /usr/local/bin/

Verify installation

untask --version

Quick start

Initialize a project, add some tasks, and open the desktop app when you want a graphical view.

# Initialize untask in your project
cd my-project
untask init

# Add tasks
untask add "Set up CI pipeline"
untask add "Write API docs" --status todo
untask add "Fix login bug" --status in-progress

# List tasks
untask list

# Mark a task done
untask done 1

# See what's next
untask next

# Open the desktop app
untask open
Tip Running untask with no subcommand shows command help. Use untask open to launch the desktop app.

Commands

init
Initialize a new untask project in the current directory
add <title>
Add a new task. Use -s, --status to set initial status
list
List tasks. Filter with -s status and -t tag. Sort with --sort
show <ref>
Show full task details by ID or slug
edit <ref>
Open task in $EDITOR (falls back to vi)
status <ref> <status>
Change a task's status to any configured column
done <ref>
Mark a task as done (sets completed timestamp)
delete <ref>
Delete a task. Use -f, --force to skip confirmation
next
Show a summary of next actions across columns
search <query>
Search tasks and docs. Use --tasks-only to skip docs
docs list
List all project docs matched by configured glob patterns
docs show <name>
Display a doc by name or path
repair
Check and repair project integrity. Use --check or --write
skill install
Install the untask skill for an AI agent (Claude)
open
Open the desktop app for this project

Global flags

These flags work with any command.

--json
Output as JSON. Useful for scripting and agent consumption
--no-color
Disable colored output. Also respects NO_COLOR env var

Task references

Commands that accept a <ref> argument resolve tasks in this order:

  1. Numeric ID — e.g. untask show 3
  2. Slug match — e.g. untask show fix-login matches a task titled "Fix login bug"

If a slug matches multiple tasks, you'll get an error listing the ambiguous matches.

Project structure

Running untask init creates the following structure inside your project:

.untask/ tasks/ # task markdown files 001-set-up-ci.md 002-write-api-docs.md docs/ # default docs location attachments/ # file attachments cache/ # temporary data (gitignored) config.yml # project configuration .gitignore # ignores .lock and cache/

Task files are named with a zero-padded ID prefix and a slug: 001-fix-login-bug.md. IDs are never reused — deleted task IDs create gaps.

config.yml

Located at .untask/config.yml. Falls back to sensible defaults if missing or invalid.

# .untask/config.yml
columns:
  - id: backlog
  - id: todo
    aliases: [to-do, to do, pending]
  - id: in-progress
    aliases: [wip, in progress, doing, working]
  - id: review
    aliases: [reviewing, in review]
  - id: done
    aliases: [complete, finished, closed]

docs:
  - .untask/docs/**/*.md

theme: mono

Columns & statuses

Columns define the task lifecycle stages used across the CLI and desktop app. Each column has a canonical id and optional aliases.

When you set a status (via untask status, untask add --status, or the desktop app), untask normalizes it against configured columns and aliases. For example, wip, in progress, and doing all resolve to in-progress.

The first column is the default status for new tasks. You can fully customize columns:

columns:
  - id: icebox
  - id: next
  - id: doing
  - id: shipped

Docs patterns

The docs array in config.yml takes glob patterns relative to the project root. Matched files appear in the desktop app and CLI docs command.

docs:
  - .untask/docs/**/*.md
  - notes/**/*.md
  - specs/*.md
Security Absolute paths and parent traversal (../) are rejected. All doc globs must be relative to the project root.

Task file format

Each task is a markdown file with YAML frontmatter. The body supports standard markdown including checklists for subtasks.

---
id: 3
title: Fix login bug
status: in-progress
tags:
  - auth
  - bug
created: 2026-03-01
updated: 2026-03-07T10:30:00Z
---
The login form returns a 500 error when the email
contains a plus sign.

- [x] Reproduce the issue
- [ ] Fix the email parser
- [ ] Add regression test

Frontmatter fields

id
Numeric identifier. Auto-assigned on creation, never reused
title
Task title (required)
status
Current column. Normalized against config aliases
tags
List of string tags for filtering
created
Date created (YYYY-MM-DD)
updated
Last modification timestamp (ISO 8601)
completed
Timestamp when marked done. Cleared if re-opened

Subtask progress

Top-level checklist items in the body (- [x] and - [ ]) are tracked as subtask progress. Indented checklists are ignored.

JSON output

Pass --json to any command for machine-readable output. Useful for piping into jq, scripting, or feeding to AI agents.

untask list --json | jq '.[].title'

untask show 3 --json
Agents The JSON output mode is designed for AI agent consumption. Combine it with untask skill install to give Claude context about your project's tasks.

Claude skill

Untask can install a skill that gives Claude (and other AI agents) awareness of your project's tasks.

untask skill install

This registers the untask skill so that AI agents can read, search, and reason about your tasks using the CLI's JSON output.

Repair

The repair command checks project integrity and can fix common issues like unindexed task files.

# Check only — reports issues without modifying files
untask repair --check

# Apply fixes
untask repair --write

The --check and --write flags are mutually exclusive. Running repair with no flags shows a usage hint.

Desktop app

Untask has a companion desktop application (Tauri + Svelte) that provides a graphical interface for the same task data.

# Open the desktop app for the current project
untask open

The desktop app reads from the same .untask/ directory, so changes sync automatically between CLI and GUI.
